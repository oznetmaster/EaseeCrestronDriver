# Model alignment review

Reviewed 22 October 2026 against TeslaPowerwallCrestronDriver's README, project metadata, packaging tools and release workflows, and the [Crestron Home Driver NuGet Publishing Standard v1](https://github.com/oznetmaster/Crestron-Home-Driver-Feed-Installer/blob/master/docs/standard/crestron-home-driver-nuget-publishing-standard-v1.md).

| Area | Easee implementation and verification |
| --- | --- |
| Installation and distribution | README includes the Feed Installer route, alternative manual `.pkg` installation, source-archive distinction, processor import, Configure, site/charger selection and upgrade instructions. |
| NuGet identity and metadata | `CrestronHomeDriver.Easee.Charger`; `CrestronHomeDriver` package type; required tags, description, author/company, repository/project links, README and licence. `IncludeBuildOutput=false` and `SuppressDependenciesWhenPacking=true`. |
| NuGet content | Exactly one root Release `.pkg` and `crestron-driver-package.json`. Required manifest fields and versions must match. Additional payload SHA256 ties the embedded driver to the GitHub asset. No `lib/` DLL payload or package dependencies. |
| Package regression checks | The actual generated wrapper must pass validation; corrupted manifest version, library DLL, altered payload and incorrect package type must fail. |
| Authentication | NuGet trusted publishing with GitHub OIDC, the existing account's profile name and a repository/workflow/environment/package-specific policy. No long-lived NuGet key is introduced. This follows the user's requested authentication preference rather than the model's older API-key secret. |
| Release provenance | Prepare from reviewed source; verify hosted checks and the existing App-reported processor gate. Stage packages, wrapper, documentation, source identity and checksums once. Publication promotes that exact successful run on its matching existing tag and does not rebuild the artifacts. |
| Runtime candidate acceptance | Validate the staged driver on a reserved processor before promotion. Source checks alone do not certify independently rebuilt driver bytes. Exact package/source/SDK identities and retained results distinguish each candidate. |
| Versioning | Four-part driver manifest and three-part release versions; Release revision zero; Debug revision advances. Main/test manifests share the release version. Test-only releases can use an independent test-host version without publishing the driver NuGet package. |
| Processor-only distribution | `release-tests.yml` stages the test host, documentation, source identity and checksums. Its optional GitHub release is explicitly test-only, does not become the latest product release and does not publish a driver/library NuGet package. |
| Post-publication checks | `post-release-validation.yml` verifies the published tag/source, GitHub checksums, required assets and the matching NuGet payload. Unlike the model, this workflow does not create source/version commits during publication, so redundant default-branch test dispatch is unnecessary. |
| NUnit | NUnit 5, adapter, analyzer and test SDK pins; model's pinned reusable NUnit policy; 54 core and eight desktop contract tests; declared 70-test processor suite; separate opt-in live suites. The old 69-test declaration was corrected after its package-count guard rejected the added regression. |
| Native entity definition | Unique combined property/command/event IDs; `vehicleConnected` property preserved and connection event renamed `vehicleConnectedEvent`. Installed Home log comparison checks definition errors after update. |
| Compiler and XML documentation | net472 shipping projects, latest C#, nullable annotations, compatibility shims, generated XML and warnings as errors. No documentation-warning suppression is copied from the model. |
| Editor and licence metadata | `.editorconfig` matches the model byte for byte. Neil Colvin metadata and MIT with Commons Clause preserved. |
| Packaging and notices | NuGet ManifestUtil 29.0.10, ILRepack and patched dependency closure. Original dependency licence/notice bytes and indices accompany the driver; the processor test host includes both SDK notices and its own NuGet dependency licence index. Documentation ZIPs carry packaged notices. |
| Shared hardware | HPNEIL only; exact machine/processor ownership, existing .241/.244 pool admission and Office room, cleanup and lease receipts. No alternative runner, label change or hardware-skip publication input. |
| Device-specific differences | Easee uses cloud account configuration, site/charger selection and the released EaseeChargerClient. Tesla Owner/Fleet/local provisioning, Powerwall pages, Word submission tooling and Tesla credentials are not applicable. Room/Home/Both placement follows the explicit Easee requirement. |
| Scope boundaries | Client-library source, NuGet identity and HTML documentation remain in EaseeChargerClient. The model driver has no separate DocFX/GitHub Pages publication workflow to copy. Crestron catalogue submission is distinct from this community GitHub/NuGet release; catalogue availability is not claimed. |

The workflow validates artifact structure and provenance automatically. Physical operation and human observations remain separately identified in VALIDATION.md; an artifact checksum is an integrity record, not an independent certification.
